# 精读九：设计评审型综合项目

这是最后一项任务，不是新 API 练习。实现一个小型“研究 → 校验 → 汇总”系统，允许 Flow 负责外层状态机，Crew/Agent 负责节点内推理，Task 负责输出契约，Tool/Memory/事件/checkpoint 负责运行时能力。

## 必须实现

1. 至少三个任务，其中一个结构化输出、一个 guardrail、一个条件分支。
2. 至少一个工具调用和一次失败后可恢复的工具结果。
3. 至少一个记忆 scope、一次事件监听、一次 checkpoint 恢复。
4. 所有模型行为必须使用真实 LLM；另提供 fake LLM 离线回归入口。报告不得包含密钥、完整敏感 prompt 或业务数据。
5. 提供“朴素脚本版”和“分层设计版”并排输出。

## 最终报告必须回答

- 画出入口、状态、编排、执行器、工具、存储和观测的调用链。
- 标出每个 LLM 决策点，以及每个 TypeScript 确定性边界。
- 列出至少三项收益和三项代价，包含一个 CrewAI 设计不适合的场景。
- 指出哪些地方忠实复现源码，哪些地方是教学简化，哪些结论是工程推论。

## 完成标准

代码、真实报告、README 教学说明齐全；正常路径和至少两个失败/恢复路径可重复运行；读者只看最终报告也能解释“为什么这样分层”。
